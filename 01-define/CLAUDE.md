# Phase 1: Define (Product Definition & User Journey)

Define what you're building and why. Lock in product scope, user journey, and domain terminology before any technical decisions.

## Your Task

Use the define-author agent to complete these deliverables:

- **prd-template.md** — Product definition (problem, value prop, scope, success metrics)
- **user-journey-template.md** — End-to-end user flow (step-by-step actions, decision points)
- **ui-ux-ideas.md** — UI mockups and interaction patterns (optional for some projects)
- **roles-and-permissions.md** — Who does what? (if your project has roles)

Update **GLOSSARY.md** with canonical domain terms as you go.

## Exit Criteria

✅ Product definition is unambiguous (no "TBD" placeholders)
✅ User journey covers happy path + error cases
✅ Scope is locked (explicit list of what's v1, what's deferred)
✅ No contradictions in terminology (GLOSSARY is authoritative)

## Reviewers

When define-author is done, these reviewers check for issues:
- **terminology-reviewer** — Is your glossary consistent?
- **scope-reviewer** — Is scope clear and realistic?
- **docquality-reviewer** — Are docs readable and cross-linked?

## Next Phase

Once Phase 1 passes review → move to **02-spec** (technical architecture).
